4. Python MCP 서비스 구축

정리된 옵시디언 지식 그래프를 LLM이 실시간 조회할 수 있도록 MCP(Model Context Protocol) 서버를 만듭니다.

4.1 MCP 서버 구조

· 옵시디언 볼트 디렉터리를 읽어서 모든 .md 파일의 프론트매터와 링크를 파싱합니다.
· 아래와 같은 툴(Tool)을 제공합니다:
  1. search_notes(query, tags, category) – 내용/태그/카테고리 검색
  2. get_note(path) – 특정 노트의 전체 마크다운 반환
  3. get_linked_notes(path) – 해당 노트와 연결된 모든 노트 목록 (백링크 포함)
  4. get_knowledge_subgraph(concept) – 특정 개념에서 출발해 N-hop 이웃 노드들의 제목과 관계 반환
· 필요하면 리소스(Resource)로 노트 내용을 직접 제공할 수도 있습니다.

4.2 MCP 서버 기본 코드 (FastMCP 사용)

```python
# mcp_server.py
import os
import re
import yaml
import glob
from pathlib import Path
from typing import Any
from mcp.server.fastmcp import FastMCP

# 설정
VAULT_PATH = "/path/to/회사규정볼트"
NOTES_DIR = os.path.join(VAULT_PATH, "10_정리")

# MCP 서버 인스턴스
mcp = FastMCP("Company Regulations Knowledge Graph")

# 메모리 내 인덱스 빌드
def parse_frontmatter(content: str):
    """프론트매터 파싱"""
    if content.startswith("---"):
        parts = content.split("---", 2)
        if len(parts) >= 3:
            fm = yaml.safe_load(parts[1])
            return fm, parts[2]
    return {}, content

def build_index():
    notes = {}
    for md_path in glob.glob(os.path.join(NOTES_DIR, "**/*.md"), recursive=True):
        rel_path = os.path.relpath(md_path, NOTES_DIR)
        with open(md_path, "r", encoding="utf-8") as f:
            raw = f.read()
        fm, body = parse_frontmatter(raw)
        # 링크 추출: [[...]] 
        links = re.findall(r"\[\[([^\]]+)\]\]", body)
        notes[rel_path] = {
            "title": fm.get("title", Path(rel_path).stem),
            "tags": fm.get("tags", []),
            "category": fm.get("category", ""),
            "related": fm.get("related", []),
            "source": fm.get("source", ""),
            "body": body,
            "links": list(set(links)),
            "path": rel_path
        }
    return notes

notes_index = build_index()

# --- Tools ---
@mcp.tool()
def search_notes(query: str = "", tags: list[str] = None, category: str = "") -> list[dict]:
    """노트 검색: 제목, 태그, 카테고리, 본문 일부 일치"""
    results = []
    for note in notes_index.values():
        if query and query.lower() not in note["title"].lower() and query.lower() not in note["body"].lower():
            continue
        if tags and not any(t in note["tags"] for t in tags):
            continue
        if category and category != note.get("category", ""):
            continue
        results.append({
            "path": note["path"],
            "title": note["title"],
            "tags": note["tags"],
            "category": note["category"],
            "snippet": note["body"][:200]
        })
    return results

@mcp.tool()
def get_note(path: str) -> str:
    """특정 노트의 전체 마크다운 콘텐츠 반환"""
    full_path = os.path.join(NOTES_DIR, path)
    if not os.path.exists(full_path):
        return "존재하지 않는 노트입니다."
    with open(full_path, "r", encoding="utf-8") as f:
        return f.read()

@mcp.tool()
def get_linked_notes(path: str) -> list[dict]:
    """특정 노트와 양방향으로 연결된 모든 노트 목록"""
    if path not in notes_index:
        return []
    linked = set(notes_index[path]["links"])
    # 직접 링크 + related 필드
    for rel in notes_index[path].get("related", []):
        linked.add(rel)
    # 백링크 찾기
    for other_path, note in notes_index.items():
        if path in note["links"] or path in note.get("related", []):
            linked.add(other_path)
    result = []
    for link in linked:
        if link in notes_index:
            result.append({"path": link, "title": notes_index[link]["title"]})
    return result

@mcp.tool()
def get_knowledge_subgraph(concept: str, hops: int = 1) -> dict:
    """특정 개념에서 N-hop 이웃 그래프를 제목과 관계로 반환"""
    # 간단하게 노드가 concept을 포함하는 노트를 시작점으로
    start_nodes = [p for p, n in notes_index.items() if concept.lower() in n["title"].lower()]
    graph = {"nodes": [], "edges": []}
    visited = set()
    queue = [(n, 0) for n in start_nodes]
    while queue:
        current, dist = queue.pop(0)
        if current in visited or dist > hops:
            continue
        visited.add(current)
        note = notes_index[current]
        graph["nodes"].append({"id": current, "title": note["title"]})
        for link in note["links"]:
            if link in notes_index:
                graph["edges"].append({"source": current, "target": link, "type": "direct"})
                if link not in visited and dist < hops:
                    queue.append((link, dist+1))
        for rel in note.get("related", []):
            if rel in notes_index:
                graph["edges"].append({"source": current, "target": rel, "type": "related"})
    return graph

if __name__ == "__main__":
    mcp.run()
```

5. 개정 사항 자동 반영 체계

5.1 변경 감지 및 재처리 워크플로

원본 문서가 변경되면(예: 새 버전 저장, 내용 수정) LLM이 다시 정리 노트를 생성하도록 합니다.
방법은 크게 두 가지입니다.

A) 파일 시스템 감시 스크립트 (권장)

파이썬의 watchdog을 이용해 00_원본 폴더를 감시하다가 변경된 파일이 생기면 해당 파일만 재처리합니다.

```python
# watcher_sync.py
import time
from watchdog.observers import Observer
from watchdog.events import FileSystemEventHandler
import subprocess

class SourceHandler(FileSystemEventHandler):
    def on_modified(self, event):
        if event.src_path.endswith(".md"):
            print(f"변경 감지: {event.src_path}")
            # LLM 변환 스크립트 호출 (해당 파일만)
            subprocess.run(["python", "process_one.py", event.src_path])

observer = Observer()
observer.schedule(SourceHandler(), "00_원본", recursive=True)
observer.start()
try:
    while True:
        time.sleep(1)
except KeyboardInterrupt:
    observer.stop()
observer.join()
```

process_one.py는 단일 원본 파일을 읽어 LLM API를 호출하고, 기존 정리 노트를 업데이트하거나 새로 생성합니다.
중요: 기존 정리 노트의 source 속성을 확인하여 같은 원본에서 파생된 노트들을 찾아 선택적으로 덮어쓰거나 버전 이력을 변경이력.md에 기록합니다.

B) 옵시디언 플러그인 + Git 훅

· 옵시디언의 “Git” 플러그인으로 볼트를 버전 관리합니다.
· post-commit 훅에서 변경된 원본 파일 목록을 추출하고 변환 스크립트를 실행합니다.
· 또는 Obsidian Shell Commands 플러그인으로 특정 명령을 트리거할 수 있습니다.

5.2 정리 노트 업데이트 전략

· 원본과 정리 노트 간 매핑 유지: 정리 노트의 프론트매터 source로 원본 파일명을 기록합니다.
· 버전 관리: 정리 노트의 updated 속성을 갱신하고, 이전 버전은 10_정리/99_메타/변경이력.md에 자동 기록.
· 충돌 방지: LLM이 기존 노트를 완전히 덮어쓰기보다, 관련 링크가 유지되도록 프롬프트에서 “기존 노트 구조를 존중하며 업데이트”라고 지시합니다.

5.3 완전 자동화 파이프라인 예시

```mermaid
flowchart LR
A[원본 md 수정] --> B(watchdog 감시)
B --> C{변경된 파일}
C --> D[process_one.py]
D --> E[LLM API 호출]
E --> F[정리 노트 생성/갱신]
F --> G[MCP 서버 인덱스 리빌드]
```

MCP 서버는 파일 시스템의 변경을 실시간으로 반영하지 않을 수 있으므로, 서버 재시작 또는 인덱스 재빌드 트리거가 필요합니다.
간단히 MCP 서버에 rebuild_index 툴을 만들어 호출하거나, 서버를 --watch 모드로 실행할 수 있습니다.
(예: mcp_server.py 실행 시 build_index() 후, 주기적 폴링)

6. 실제 사용 시나리오 (Claude Code 연동)

사용자가 Claude Code에서 다음과 같이 질의합니다.

“출장 시 교통비 정산 절차 알려줘”

Claude Code는 자동으로 MCP 툴을 사용합니다:

1. search_notes(query="교통비 정산", tags=["출장"]) → 관련 노트 경로 확보
2. get_note(path="출장/국내출장_교통비.md") → 정확한 규정 습득
3. 필요시 get_linked_notes(path)로 신청서 양식, 결재라인 등 추가 정보 파악
4. 답변 생성

규정이 바뀌면 원본 파일만 수정하면 자동화 파이프라인이 정리 노트를 갱신하므로, LLM은 항상 최신 정보를 제공합니다.

7. 정리된 체계 요약

구성 요소 설명 핵심 포인트
옵시디언 볼트 구조 00_원본 / 10_정리 분리 원본 보존, 정리는 지식 그래프
원본 MD 형식 YAML 메타데이터 + 원문 title, category, version 필수
LLM 변환 프롬프트 개념 분해, 링크, 인덱스 생성 JSON 출력으로 자동 저장
MCP 서버 파이썬 FastMCP, 파일 파싱 search, get_note, subgraph
자동화 watchdog + process_one.py 변경 파일만 재처리, 인덱스 갱신
개정 반영 source 기반 덮어쓰기 + 변경 이력 LLM 업데이트 프롬프트 활용

이 체계를 구축하면 회사 규정이 “살아있는 지식 그래프”가 되어, MCP를 지원하는 모든 LLM에서 신뢰성 있는 규정 정보를 실시간으로 조회·추론할 수 있습니다.

추가로 궁금한 부분(예: LLM 프롬프트 상세 설계, Git Actions 연동 등)이 있다면 말씀해주세요.
