# 2. 답변 정리

다음은 Obsidian 볼트를 중심으로 회사 규정 문서들을 지식 그래프화하고, 이를 Python MCP 서버로 제공해 LLM이 토큰을 최적화하며 활용할 수 있도록 설계하는 상세 가이드입니다.

1. 전체 아키텍처 개요

```
Obsidian Vault (로컬)
 ├── 원본/                     ← 원본 규정 .md 파일 보관
 │    ├── 복리후생/
 │    ├── 출장규정/
 │    └── ...
 ├── 정리/                     ← LLM으로 가공된 지식 그래프 문서
 │    ├── 복리후생/
 │    ├── 출장규정/
 │    ├── _index/              ← 카테고리별 MOC, 태그 인덱스
 │    └── 규정_지식그래프.md    ← 전체 요약 + 링크 + 임베딩 메타
 └── .obsidian/                ← 설정

Python MCP 서버 ──► 정리 폴더를 읽어 도구/리소스 제공
LLM 클라이언트(Claude 등) ──► MCP 프로토콜로 서버에 연결
```

2. 폴더 구조 및 명명 규칙

2-1. 원본/ 폴더

· 실제 배포되는 규정 원문을 그대로 마크다운으로 변환하여 저장합니다.
· 파일명 예: 복리후생_휴가제도_v2.1.md, 출장규정_국내출장_v1.0.md
· YAML 프론트매터 필수:

```yaml
---
title: "휴가 제도"
category: "복리후생"
version: "2.1"
date: 2025-03-01
author: "인사팀"
tags: [휴가, 연차, 병가]
---
```

2-2. 정리/ 폴더

· 가공된 문서가 위치하며, 원본의 폴더 계층을 그대로 유지합니다.
· 정리된 각 문서의 파일명은 원본과 동일하게 유지하되, _summary와 같은 접미사를 붙일 수도 있습니다. (여기서는 동일 파일명 + 프론트매터/내용 가공)
· 구조:

```
정리/
├── 복리후생/
│   ├── 휴가제도.md
│   ├── 경조사지원.md
│   └── ...
├── 출장규정/
│   └── 국내출장.md
├── _index/                     # 지식 그래프 탐색용 MOC (Map of Content)
│   ├── 복리후생_MOC.md
│   ├── 출장규정_MOC.md
│   └── tags/근태.md
└── 규정_지식그래프.md          # 전체 요약 + 문서별 임베딩 참조
```

3. 정리 문서 양식 (지식 그래프 노드)

각 정리된 .md 파일은 하나의 지식 그래프 노드로 동작합니다.
프론트매터와 본문 상단에 핵심 요약을 넣고, 관련 문서로의 위키링크를 포함시킵니다.

정리 문서 템플릿 (예: 정리/복리후생/휴가제도.md)

```markdown

category: "복리후생"
original: "원본/복리후생/휴가제도_v2.1.md"
version: "2.1"
last_updated: 2025-03-01
tags: [휴가, 연차, 병가, 근태]
links: [[경조사지원]], [[근태기준]], [[출장규정/국내출장]]

# 📌 핵심 요약

- **특별휴가**: 경조사 시 최대 5일 (경조사지원 문서 참조)
- **휴가 신청 절차**: 사내 시스템 > 근태팀 승인 (영업일 2일 전)

---

## 1. 적용 대상
정규직, 계약직 전원...

## 2. 상세 규정
...

## 3. 관련 문서
```

4. 임베딩과 토큰 최적화 구조

4-1. 임베딩 생성 전략

· 각 정리 문서의 핵심 요약 부분을 text-embedding-3-small 또는 로컬 sentence-transformers로 임베딩하여 벡터 DB에 저장합니다.
· Obsidian 내에서는 플러그인(Text Embeddings 등)을 사용하거나, MCP 서버가 정리 폴더를 스캔하여 임베딩을 계산하고 ChromaDB 또는 FAISS 인덱스 파일을 볼트 외부에 저장합니다.
· 임베딩 벡터 자체를 프론트매터에 넣을 수도 있지만, 관리 부담이 크므로 외부 벡터 스토어를 권장합니다.

4-2. 토큰 최적화를 위한 MCP 도구 설계

MCP 서버가 제공할 도구는 항상 우선 요약 수준의 정보를 반환하고, LLM이 필요하다고 판단할 때만 전문(full text)를 요청하도록 합니다.

예시 도구:

1. search_regulations(query: str, top_k: int = 5, detail: str = "summary")
   · detail="summary" → 검색된 문서의 핵심 요약과 위키링크만 반환
   · detail="full" → 전문 반환
2. get_document_content(doc_path: str, section: str = "summary")
3. list_categories() → 카테고리 목록과 각 문서 개수
4. get_related_docs(doc_path: str) → 해당 문서의 링크된 문서 목록과 요약

이렇게 하면 LLM이 대부분의 질문에 대해 수백 토큰으로 답변 생성이 가능해지며, 상세 규정이 필요할 때만 전체 문서(수천 토큰)를 가져옵니다.

5-3. MCP 서버 코드 예시 (FastMCP 사용)

```python
# server.py
import os, yaml
from pathlib import Path
from mcp.server.fastmcp import FastMCP
import markdown
from sentence_transformers import SentenceTransformer
import chromadb
from chromadb.config import Settings

# 설정 로드
with open("config.yaml") as f:
    config = yaml.safe_load(f)

VAULT = Path(config["obsidian_vault_path"])
ORGANIZED = VAULT / config["organized_folder"]

# 임베딩 모델 및 벡터 DB 초기화
embedder = SentenceTransformer(config["embedding_model"])
chroma_client = chromadb.PersistentClient(path=config["vector_db_path"])
collection = chroma_client.get_or_create_collection(name="regulations")

mcp = FastMCP("규정 지식 그래프")

def load_markdown(filepath: Path):
    with open(filepath, 'r', encoding='utf-8') as f:
        text = f.read()
    # 간단 프론트매터 파싱
    frontmatter = {}
    if text.startswith('---'):
        end = text.find('---', 3)
        if end != -1:
            import yaml
            frontmatter = yaml.safe_load(text[3:end])
            content = text[end+3:].strip()
        else:
            content = text
    else:
        content = text
    return frontmatter, content

def extract_summary(content: str) -> str:
    # 요약 섹션 추출 (간단 구현)
    lines = content.split('\n')
    summary = []
    capture = False
    for line in lines:
        if line.strip().startswith('# 📌 핵심 요약'):
            capture = True
            continue
        if capture and line.startswith('#'):
            break
        if capture:
            summary.append(line.strip())
    return ' '.join(summary)

def get_all_organized_files():
    for md_file in ORGANIZED.rglob("*.md"):
        if md_file.name == "규정_지식그래프.md":
            continue
        yield md_file

# 서버 시작 시 임베딩 인덱싱
@mcp.tool()
def rebuild_index():
    """모든 정리 문서를 다시 인덱싱합니다."""
    collection.delete(collection.get()['ids'])  # 초기화
    for md_file in get_all_organized_files():
        frontmatter, content = load_markdown(md_file)
        summary = extract_summary(content)
        if not summary:
            summary = content[:200]  # fallback
        embedding = embedder.encode(summary).tolist()
        rel_path = str(md_file.relative_to(ORGANIZED))
        collection.add(
            documents=[summary],
            embeddings=[embedding],
            metadatas=[{"path": rel_path, "title": frontmatter.get("title", "")}],
            ids=[rel_path]
        )
    return f"{collection.count()}개 문서 인덱싱 완료"

@mcp.tool()
def search_regulations(query: str, top_k: int = 5, detail: str = "summary"):
    """규정 검색 (임베딩 기반)"""
    query_emb = embedder.encode(query).tolist()
    results = collection.query(query_embeddings=[query_emb], n_results=top_k)
    output = []
    for i, doc_id in enumerate(results['ids'][0]):
        meta = results['metadatas'][0][i]
        filepath = ORGANIZED / meta['path']
        if detail == "summary":
            output.append({
                "title": meta['title'],
                "summary": results['documents'][0][i],
                "path": meta['path'],
                "link": f"[[{meta['path'].replace('.md','')}]]"
            })
        else:
            _, full_content = load_markdown(filepath)
            output.append({
                "title": meta['title'],
                "content": full_content,
                "path": meta['path']
            })
    return output

@mcp.tool()
def get_document_content(doc_path: str, section: str = "summary"):
    """특정 문서의 요약 또는 전문을 가져옵니다."""
    full_path = ORGANIZED / doc_path
    if not full_path.exists():
        return {"error": "문서 없음"}
    _, content = load_markdown(full_path)
    if section == "summary":
        return {"summary": extract_summary(content)}
    else:
        return {"content": content}

@mcp.tool()
def list_categories():
    """카테고리 목록"""
    cats = {}
    for md_file in get_all_organized_files():
        cat = md_file.parent.name
        cats[cat] = cats.get(cat, 0) + 1
    return cats

if __name__ == "__main__":
    mcp.run()
```

6. 토큰 최적화 전략

1. 계층적 정보 제공
      질문 → 카테고리 선택 → 문서 요약 목록 → 특정 문서 요약 → 전문.
      LLM이 여러 단계를 거치도록 해 불필요한 대량 텍스트 전송을 방지합니다.
2. 프롬프트 캐싱 가능한 구조
      시스템 프롬프트에 전체 규정 요약(규정_지식그래프.md)을 포함시키면, Claude의 경우 프롬프트 캐시 적중률이 높아집니다.
      이 파일은 1000토큰 이내로 유지합니다.
3. 임베딩 검색으로 연관 문서만 전달
      사용자 질문과 의미적으로 가장 가까운 문서 2~3개의 요약만 컨텍스트로 제공합니다.
4. 문서 청크 단위 접근
      하나의 규정이 길 경우, # 섹션 단위로 분할하여 get_document_content(doc, section="## 2. 신청 절차") 식으로 세부 접근을 허용합니다.

7. 개정 사항 자동 반영 체계

7-1. 파일 변경 감시 → 자동 재가공 파이프라인

원본 폴더에 신규/변경 파일이 생기면, LLM을 호출해 정리 문서를 자동 재생성하는 스크립트를 작성합니다.

스크립트 예시 (auto_update.py)

```python
import time, hashlib
from watchdog.observers import Observer
from watchdog.events import FileSystemEventHandler
from pathlib import Path
import openai  # 또는 anthropic

class RegulationHandler(FileSystemEventHandler):
    def on_modified(self, event):
        if event.src_path.endswith('.md') and '원본' in event.src_path:
            self.process(Path(event.src_path))

    def process(self, original_path: Path):
        # 1. 원본 읽기
        # 2. LLM으로 요약 + 분류 + 정리문서 생성
        # 3. 정리 폴더에 저장 (동일 상대경로)
        # 4. MOC 및 전체 요약 갱신
        # 5. MCP 서버에 rebuild_index 호출 (또는 서버 자체 감시)
        pass
```

· Templater + QuickAdd: 새 원본 문서를 특정 폴더에 생성하면, QuickAdd 매크로가 위 프롬프트로 LLM API를 호출해 정리 문서를 자동 생성할 수도 있습니다.
· Git 훅: 원본 폴더를 Git으로 관리하고, 커밋 시 CI 파이프라인에서 정리 문서 생성 및 MCP 인덱스 갱신.

9. 확장을 위한 팁

· 프론트매터에 aliases 필드를 두면 Obsidian에서 다양한 이름으로 검색 가능
· 데이터뷰 쿼리로 동적 대시보드: TABLE summary FROM #휴가
· MCP 리소스로 각 문서를 직접 노출하여 Claude가 regulations://복리후생/휴가제도 형태로 접근 가능
· 버전 관리를 위해 원본과 정리 문서 모두 Git 저장소로 관리하면 변경 이력 추적과 롤백이 용이

이 설계를 따르면 회사 규정이 지식 그래프 형태로 체계화되고, LLM 에이전트가 최소 토큰으로 정확한 답변을 할 수 있으며, 규정 개정 시 자동으로 동기화되는 시스템을 구축할 수 있습니다.
